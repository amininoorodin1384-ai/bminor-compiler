# قواعد واژگانی پیاده‌سازی‌شده تا این مرحله

این سند وضعیت فعلی Lexer را از قواعد نهایی زبان جدا می‌کند. در این گام فاصله‌ها، توضیح‌ها، شناسه‌ها، کلیدواژه‌ها، عدد صحیح، رشته، کاراکتر و خطاهای مربوط به این دسته‌ها پیاده‌سازی شده‌اند؛ عملگرها و جداکننده‌ها در گام بعدی اضافه می‌شوند.

## قواعد فعلی

| دسته | قاعده |
|---|---|
| حرف | یکی از `A-Z` یا `a-z` |
| شروع شناسه | حرف یا `_` |
| ادامهٔ شناسه | حرف، رقم `0-9` یا `_` |
| شناسهٔ بیش از ۲۵۶ بایت | توکن `INVALID` |
| عدد صحیح | یک یا چند رقم ده‌دهی، بدون علامت؛ منفی به‌عنوان عملگر جداگانه اضافه خواهد شد |
| رشته | متن داخل `"..."`؛ escape به‌صورت backslash به‌همراه نویسهٔ بعدی خوانده می‌شود؛ حداکثر ۲۵۶ نویسهٔ مقدار |
| کاراکتر | دقیقاً یک نویسهٔ مقدار داخل `'...'`؛ escape یک نویسهٔ مقدار حساب می‌شود |
| کلیدواژه | `array`, `boolean`, `char`, `else`, `false`, `for`, `function`, `if`, `integer`, `print`, `return`, `string`, `true`, `void`, `while` |
| فاصله | space، tab، LF یا CR؛ از جریان توکن حذف می‌شود |
| توضیح خطی | از `//` تا پایان خط؛ حذف می‌شود |
| توضیح بلوکی | از `/*` تا نخستین `*/`؛ حذف می‌شود |

Lexer ابتدا کل واژه را به‌عنوان شناسه می‌خواند و سپس آن را با مجموعهٔ کلیدواژه‌ها مقایسه می‌کند؛ بنابراین یک واژهٔ کلیدواژه‌ای به‌اشتباه شناسه نخواهد شد.

در حال حاضر نویسه‌های دیگر—از جمله عملگرها و جداکننده‌هایی که هنوز افزوده نشده‌اند—یک توکن `INVALID` مستقل می‌سازند و موقعیت خطا نگه داشته می‌شود. توضیح بلوکی، رشته یا کاراکتر بسته‌نشده نیز به‌صورت `INVALID` گزارش می‌شود. طول شناسه بیش از ۲۵۶ بایت و رشته با بیش از ۲۵۶ نویسهٔ مقدار نامعتبر است. هر توکن شامل نوع، lexeme و نام فایل/خط/ستون است؛ در پایان نیز توکن `EOF` ساخته می‌شود.

## محدودیت‌های فعلی

- عملگرها و جداکننده‌ها هنوز پیاده‌سازی نشده‌اند.
- شناسه‌ها بر مبنای ASCII/بایت پردازش می‌شوند؛ شناسه‌های غیر ASCII در محدودهٔ پیاده‌سازی فعلی نیستند.
- آزمون‌های نوع توکن، حد طول و خطاهای بسته‌نشده در `tests/lexer_tests.cpp` نگهداری می‌شوند.
- قواعد قطعی و کامل باید پس از تطبیق جدول عملگرها با فایل رسمی درس تکمیل شوند.
